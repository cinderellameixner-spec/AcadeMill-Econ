# 研究记录指南

一个独立选题、课题或研究对应一个目录。同一研究的多轮讨论和六模块成果持续归入该目录；另一个独立研究创建新目录。

## 新建

直接告诉 agent：“新建独立研究，名称是……，开始选题讨论。”agent 会先创建目录，再将实际需求写入第一轮 request.md。

也可以从根目录手动创建：

```powershell
python tools/research_project.py new '数字化转型与就业'
```

工具分配未使用的 ID（例如 R001）并创建第一轮记录。它只建立骨架，不执行研究、不自动转录聊天、不替 agent 更新后续进展。

```text
research/R001_数字化转型与就业/
├─ PROJECT.md              当前问题、约束、阶段、成果、下一步
├─ decisions.md            决策及其依据、用户确认状态
├─ sources.md              本研究输入与来源索引
├─ inbox/                  原始输入
├─ work/                   临时材料
├─ output/                 成果，建议按轮次分子目录
└─ runs/时间戳/
   ├─ request.md           本轮需求和补充
   ├─ summary.md           讨论摘要、证据、限制、下一步
   └─ task.md              本轮完成状态与成果链接
```

## 继续与切换

新开聊天后说：“继续 R001，先读取状态和最近摘要，然后……”。agent 按文件恢复研究，并创建新一轮记录。手动建立轮次：

```powershell
python tools/research_project.py list
python tools/research_project.py run R001 '进一步评估数据可得性'
```

同一聊天明确归属后，可以继续讨论；独立的新课题须明确“新建”。每次有实质进展，agent 更新本轮记录与 PROJECT.md，回复中给出路径。任务中断后以已保存内容恢复，未保存的内容无法靠这些文件重建。

## 材料和历史

本研究的新材料放在其 inbox/。根 inbox/ 的旧材料保留原位置，只按用户指定登记或复制。已有成果修订保留版本；讨论摘要追加或按轮次分开，不用新结论静默替换旧决定。

聊天历史由客户端管理；本目录是研究档案，保存需求、摘要、证据索引与实际成果。手动在聊天中作了新决定时，可要求“把刚才的决定和下一步保存到本研究”。

不同研究共用技能和 Zotero 库，agent 不自动复用另一个研究的内容。需要复用时说“将 R001 的某文件作为 R002 的输入”，并记录来源。避免两个会话同时编辑同一研究。

研究内容默认在 .gitignore 中排除，仍保存在本机磁盘；这不是备份。需要长期保存时另行备份 `research/R*/`。
