# 独立研究项目与讨论记录规则

根目录 AGENTS.md 的路由、事实边界和归档规则继续适用。这里的目录隔离是 agent 执行约定，不是操作系统权限隔离。

## 选择研究项目

1. 新选题、新课题、新研究：创建独立目录；模糊兴趣也可用临时名称，后续改 PROJECT.md 中的显示名称，保留研究 ID 与目录路径。
2. 继续研究：使用用户指定的研究 ID 或路径。新会话只说“继续”且未指明项目时，先列项目并询问；不要按修改时间或唯一项目猜测归属。
3. 同一会话已经明确归属且没有切换指令时，可以继续该项目。用户明确提出另一个独立选题时建立新项目；已有项目内比较多个候选方向可以保留在同一项目。
4. 用户直接给出研究请求但未说明归属：若当前会话没有明确项目，创建新项目并告知路径。若是否切换不明确，先询问归属，期间不写入任何已有研究。
5. 不建立全局 active_project 文件；不同会话各自指定项目。研究目录 ID 唯一，不按相似题名自动合并。

## 创建与恢复

从项目根目录运行：

```powershell
python tools/research_project.py new '研究名称'
python tools/research_project.py list
python tools/research_project.py run R001 '本轮任务描述'
```

`new` 建立项目和第一轮记录；`run` 为已有研究建立新一轮记录。新会话恢复先读取 PROJECT.md、decisions.md、sources.md 和最近一轮 summary.md，再按需读成果与输入。不要一次加载全部历史；未完成的轮次应明确标注中断，不当作完成成果。恢复旧轮次须由用户明确指定，否则建新轮次并关联旧轮次。

## 每个研究目录

- PROJECT.md：研究 ID、问题、用户约束、当前阶段、已完成成果、待核验事项、下一步、最近轮次路径。
- decisions.md：追加记录用户决定与建议；标明日期、轮次、依据和是否经用户确认。模型建议不当作用户决定。
- sources.md：输入文件的项目相对路径、真实来源/DOI、Zotero 库与条目键、核验状态；无来源标待核验。
- inbox/：本研究输入；work/：临时文本、缓存与中间材料；output/：正式成果，按轮次命名或设子目录。
- runs/<轮次>/request.md：本轮用户需求与约束，后续补充按顺序追加。
- runs/<轮次>/summary.md：讨论要点、证据、建议、用户选择、执行结果、限制与下一步。它是摘要，不声称完整聊天转录，不记录隐藏推理或密钥。
- runs/<轮次>/task.md：进行中/完成/中断、已完成项、未完成项、成果路径。

每次研究回复结束前，保存本轮实质进展并更新 PROJECT.md；完成任务后更新 task.md，向用户给出保存路径。短澄清也追加 request.md 与摘要，未作评估时不生成假报告。文件写入失败必须报告，保留可恢复的文本，不声称已保存。已有成果不静默覆盖；修订保存新版本并关联旧版本。

## 隔离边界

- 只读取本研究明确登记的材料。用户指定根 inbox/ 或外部文件时，登记来源并复制到本研究 inbox/（大文件可登记原路径）；不擅自搬走原文件。
- 不扫描其他研究的内容或把其结论当成本研究输入。用户明确要求复用/比较时，记录来源研究 ID、具体文件、版本和用途。
- Zotero 是共享文献库：首次检索可以按本研究关键词获取候选，明确记录本研究选用的条目。恢复时优先读已登记条目；拓展检索单独说明范围。研究专属综合笔记标题带研究 ID，不覆盖其他研究的笔记。写入授权和查重读回遵循根规则。
- 六模块均写入同一所属研究，不为每个模块另建研究。任务输出路径规则优先于旧模板中的根 output/ 路径；阅读归档仍须读 paper-reading/AGENTS.md。
- 两个会话可操作不同研究；同时编辑同一研究有冲突风险，不宣称具备并发合并能力，应避免同时更新其状态和成果。
